# 삼국쟁투 (Battle of Three Kingdoms) 설계서

- 날짜: 2026-11-10
- 상태: 사용자가 「MVP 개발까지 추천 옵션으로」 승인(설계서·계획서 중간 검토 생략 요청)
- 참고 자료: 진수 『삼국지』(정사), 나관중 『삼국지연의』
- 2026-11-11: 가제 「군웅할거」에서 「삼국쟁투」로 이름 변경

## 1. 한 줄 소개와 목표

후한 말(191년) 중원을 무대로, 혼자서 AI 군웅들과 겨루는 **휴대폰·PC 브라우저용 턴제 전략 게임**. 1턴 = 1달.

| 항목 | 결정 |
|---|---|
| 목적 | 웹, 혼자 또는 지인이 각자 플레이(서버 없음, 저장은 브라우저) |
| 전투 | 자동 전투 + 관전. 출진 전 장수·병종·작전을 고른다 |
| 규모 | 최종 도시 30~40, 장수 200~300, 시나리오 2~3. **v0.1은 도시 15, 장수 50 안팎, 191년 시나리오 1개** |
| 인재 | 역사 2세 등장 + 가상 인재(출신 지역 경향). 가상 인재는 옵션으로 끌 수 있음 |
| 통치 | 수도는 직접, 나머지는 태수 방침(위임). 어느 도시든 직접 관리로 전환 가능. **위임 AI = 적 AI 같은 코드** |
| 전쟁 리듬 | 부상병 복귀(이긴 쪽 40%, 진 쪽 20%) + 넉넉한 징병, 대신 인구·민심 감소 |
| 공성 | 포위 → 식량·사기 감소, 파괴공작 → 성 내구도 감소, 수성 시설은 내구도로 결정, 성문 돌파 시 기병 돌입 |
| 판매 원칙 | 기능을 잠그지 않는다 |

## 2. 설계 방향: 풀고 싶은 문제 → 이 게임의 규칙

| 풀고 싶은 문제 | 이 게임의 규칙 |
|---|---|
| 궁병만 셈, 기병 무용 | 상성표: 기병→궁병 1.4배, 보병→기병 1.15배. 궁병은 공격력이 낮고(0.8) 근접하면 절반이며, 앞줄 없이 궁병만으로는 무너진다. 기병은 공격력 1.35와 돌격 보너스. 시뮬레이션으로 「한 병종 피해 비중 40% 이하, 기병 25% 이상」 확인 |
| 수비가 너무 셈, 사다리뿐 | 포위·파괴공작으로 성 내구도와 수성 시설을 줄인 뒤 공격. 성문을 깨면 성 안 구역이 열리고 기병이 들어감 |
| 기병이 공성에서 할 일 없음 | 성문 돌파 후 기병 돌입(성벽 방어 보정 무시, 돌격 보너스) |
| 총사령관 사망 = 즉시 패배, 지원군 순서 문제 | 총대장은 플레이어가 지정. 총대장 부대가 무너지면 **전군 사기 −30**(즉시 패배 아님). 전투는 한쪽 부대가 모두 무너질 때 끝 |
| 징병이 너무 느림 | 징병량 = 인구 비례로 넉넉히. 대가로 인구 감소, 민심 −3 |
| 장수가 다 죽으면 끝 | 2세 등장 + 가상 인재 |
| 책략이 이간뿐 | v0.1은 파괴공작(성 내구도). 이간·이민족·정찰 방어는 다음 판 |

## 3. 게임 구조

### 3-1. 데이터 표 (`src/data.js`)
- `CITIES`: id, 이름, 지도 좌표, 지역(서량/하북/중원/형주/강동/서주), 인접 도시, 시작 수치(인구·농업·상업·성벽)
- `FACTIONS`: id, 이름, 군주, 색
- `GENERALS`: id, 이름, 출생년, 사망년(정사 기준 근사), 등장년, 소속 세력, 시작 도시, 능력치(통솔·무력·지력·정치), 병종 적성(보·궁·기: S/A/B/C), 부모(2세 연결)
- `UNIT`: 병종 표(이동, 사거리, 공격, 방어, 상성)
- `REGION_BIAS`: 가상 인재 지역 경향
- `NAMES`: 가상 인재 성씨·이름 조각

능력치와 적성은 정사·연의를 근거로 **이 프로젝트에서 새로 정한 값**이다.

### 3-2. 상태 (`G`)
`{ saveVer, year, month, seed, playerFaction, factions, cities, gens, armies, sieges, log, opts }`
- 도시: owner, pop, agri, comm, wall, wallMax, gold, food, troops, wounded, train, loyalty, policy, direct, policyTarget
- 장수: faction(null = 재야), city, task, alive, virtual

### 3-3. 한 턴의 흐름 (`endTurn`)
1. 각 세력의 AI가 직할이 아닌 도시의 방침에 따라 장수 할 일 배정(`planCity`) — 플레이어 도시도 같은 함수
2. AI 세력 군사 판단(`aiMilitary`): 공략 방침 도시가 우세하면 출진 → 포위
3. 장수 할 일 실행(개발·징병·훈련·보수·탐색·등용·파괴공작·이동)
4. 포위 진행: 포위당한 도시 식량 −, 사기 −. 수비 측 구원군 판단. 공격 판단(AI는 승산 추정, 플레이어는 직접 명령)
5. 경제: 세금(상업·민심), 식량(농업), 병력 유지비, 부상병 회복 25%/턴, 3턴마다 수도로 송금
6. 1월: 나이 +1, 사망, 2세 등장, 가상 인재 생성
7. 승패 확인, 저장

### 3-4. 전투 (`simulateBattle`)
- 결정적: 같은 seed면 같은 결과(시험·관전 재생용). 결과에 매 라운드 그림(frames) 기록
- 들판: 14×8 칸. 부대마다 장수 1명, 병종 1개, 병력, 사기
- 피해 = 병력 × 0.08 × (0.5 + 무력/300 + 통솔/300) × 적성 × 상성 × 거리 보정 / 방어
- 공성: x=10 열이 성벽, (10,4)가 성문. 수비 부대는 성벽 위(피해 감소 = 0.25 + 0.30×내구도비, 성문이 깨지면 절반). 수성 시설 = ⌊내구도/1000⌋개(최대 4), 매 라운드 사거리 안 공격 부대 사격
- 보병·궁병은 성벽 앞에서 1라운드 사다리 → 성벽 전투. 기병은 사다리 불가
- 성문 체력 = 내구도 × 0.4. 깨지면 수비 사기 −5, 성 안 칸(11~13열)이 열리고, 들어간 부대는 성벽 보정 없이 공격. 기병은 돌입 첫 공격 1.5배
- 공성 36라운드 안에 못 끝내면 공격 측 퇴각(포위는 유지)
- 작전: 돌격(공격 +10%, 방어 −10%) / 균형 / 신중(반대)

### 3-5. 전후 처리
- 잃은 병력 중 이긴 쪽 40%, 진 쪽 20%가 부상병
- 도시 함락: 수비 장수는 인접 아군 도시로 후퇴, 없으면 재야. 민심 −10
- 세력 도시가 0이면 멸망. 군주 사망 시 2세 또는 통솔 최고 장수가 계승

### 3-6. 저장
`localStorage['gunung_save']`, `saveVer`=1, `migrate(old)`가 옛 판을 새 판으로 옮긴다.

## 4. 화면
- 첫 화면: 새 게임(세력 선택) / 이어하기 / 옵션(가상 인재 켜기·끄기)
- 지도: 도시를 누르면 정보창. 직할 도시는 장수마다 할 일 선택, 위임 도시는 방침 선택. 출진·포위 명령. 「턴 종료」
- 전투 관전: 캔버스 재생, 2배속, 건너뛰기, 결과 요약
- 보고서: 이번 턴에 일어난 일
- 휴대폰(390×844)에서 넘침 없이 동작

## 5. v0.1에서 하지 않는 것
외교·이간·이민족·특수병·연의 이벤트·소리·핫시트·장수 초상화·다른 시나리오. 도시 이동은 인접 1턴.

## 6. 성공 기준(시험·시뮬레이션)
- 단위 시험 전부 통과
- 같은 병종끼리 공격 측 승률 50% 근처(전장이 한쪽에 유리하지 않음). 궁병은 앞줄 없이는 진다(2026-11-10 조정)
- 혼성군 전투에서 한 병종의 피해 비중 40% 이하, 기병 25% 이상
- 공성(공격 4×10000 vs 수비 3×9000, 성벽 3000): 준비 없이 20~35%, 포위 2턴 뒤 55~70%
- AI끼리 120턴 12판: 오류 0, 판마다 도시 주인이 바뀌는 일이 5회 이상(전쟁이 실제로 일어남), 한 세력이 60턴 안에 통일하지 않음
- 브라우저 PC·휴대폰: 새 게임 → 턴 5회 → 출진 → 관전 → 저장·이어하기, 콘솔 오류 0
